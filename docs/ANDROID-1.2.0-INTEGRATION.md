## 多画布与共享资源

每张画布独立保存主提示词、负面词、角色、分区、预设、模型、尺寸、种子与采样参数。
Vibe、角色参考、图生图/重绘图片等资源沿用上游的共享语义。延迟完成的底图导入更新共享图片，尺寸仅回写来源画布；来源画布已删除时放弃草稿回写。

桌面常驻编辑器以 `canvasId + 主体/角色/分区 ID` 标记目标。切换画布、退出应用及 macOS 更新退出前提交各编辑会话，避免侧栏未提交的输入丢失。编辑与撤销写回原目标，不能覆盖当前另一张画布。

助手与反推在请求开始时捕获来源画布。响应到达后回写该画布，切换页面或画布不改写目标；删除来源后仍可显示响应，但不再改动草稿。队列沿用提交快照，循环沿用起始画布，生成结果保存与用户正在浏览的作品选择相互独立。

## 数据与凭据兼容

应用显示名仍为 **Plana App Desktop**。macOS bundle ID、内部执行文件名、Keychain service，Windows 执行文件名与存储身份，以及既有作品目录均沿用桌面版本。

工作区从 v1/v2 读取到 v3，多画布写入 `canvases`，顶层 `state` 保留当前画布兼容快照。旧档首次迁移前复制为 `workspace/state.json.pre-v3.bak`；角色/分区 ID 续点覆盖所有画布。迁移备份的 blob 引用纳入清理保护。

当前工作区文件损坏时，保留 `state.json.corrupt.bak` 并尝试读取迁移备份。引用记录损坏时，后台与手动清理停止 blob 回收，避免把暂时无法读取的图片当成垃圾删除。

工作区和图库同时保存同一张参考图时，共用正在进行的 blob 写入，避免争用同一临时文件而丢失参数快照。写入失败会向所有等待者报告，随后允许重试。

需要回退时先退出应用并备份整个支持目录，再用 `.pre-v3.bak` 恢复 `state.json`，最后安装旧版。该备份只包含迁移前的工作区；它不会恢复升级后新增的画布或编辑。直接用旧版写回 v3 文件不能保证多画布保留。

Android 的 Keystore 失败后明文文件退路仅在 Android 启用。macOS 继续使用原登录钥匙串，Windows 继续使用平台加密存储；桌面忽略 Android 的明文退路标记，写入失败正常上报。

远端上传版继续保留 edition、上传设置、任务重试及「收藏自动上传」。两版使用同一版本号，自动更新按 edition 选择包。

## 验证范围

新增集成回归使用合成存档和模拟接口，覆盖迁移备份、blob 清理与回退、损坏恢复、折叠关联、桌面凭据、画布/角色/分区编辑与撤销、延迟助手回写及删除来源、延迟底图尺寸、常驻输入提交，以及 80%/100%/140% 字号的宽窄画布标签行。

两版均执行 Flutter 静态分析和完整测试。GitHub Actions 另执行版本/edition 构建计划校验、标准版 Windows Release 与原生剪贴板单测、两版 macOS ARM64 构建、签名、包身份、钥匙串、剪贴板与启动冒烟。依赖保留 `gal 2.3.3`，避免当前 MSVC 的 `/await` 构建错误。

这些验证不等于真实 Finder/资源管理器、Word/画图互通的手工测试，也没有消耗真实账号点数验证生成接口。实际测试计数和构建产物以对应提交的 Actions 记录为准。
